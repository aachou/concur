## 1. 引言

本章研究最简单的共享存储器计算模型：并发线程仅通过读取和写入共享的存储单元（即**寄存器**）进行通信。本章围绕寄存器这一核心抽象，研究其一致性谱系（安全/常规/原子），以及如何从最弱的寄存器逐级构造出功能更强的寄存器。

- 背景：丘奇-图灵理论（串行可计算性）奠基；本章对并发可计算性做类似研究
- 研究价值：这些弱寄存器构造虽不实用，但能训练直觉——判断哪些算法在并发共享存储环境中有效，从而及早放弃无效方案，节省时间与成本
- 简化：采用无界时间戳的构造（更简单、突出原理），有界方案留给读者参考

## 2. 寄存器与一致性谱系

### 2.1 寄存器接口与分类

```java
public interface Register<T> {
    T read();
    void write(T v);
}
```

寄存器按读写线程数量分类：

| 缩写 | 含义 |
|------|------|
| **SRSW** | 单读取线程，单写入线程 |
| **MRSW** | 多读取线程，单写入线程 |
| **MRMW** | 多读取线程，多写入线程 |

通常要求寄存器的实现是**无等待**的——互斥依赖调度程序，而无等待性排除了任何类型的互斥，保证独立演进。

### 2.2 三种一致性（从弱到强）

| 级别 | 与写不重叠时 | 与写重叠时 |
|------|------------|-----------|
| **安全**（safe） | 返回最近写入的值 | 可返回取值范围内任意值 |
| **常规**（regular） | 返回最近写入的值 | 返回重叠写操作的值或最近写入的值 |
| **原子**（atomic） | 返回最近写入的值 | 返回由线性化次序决定的值 |

> "安全"是历史命名，实际它提供的保证最弱，最不安全。

### 2.3 形式化条件

以写入次序 W⁰, W¹, ...（原子寄存器按线性化次序索引）和 R^i^（返回 v^i^ 的读操作）为基础：

- **(4.1.1)** 读操作不能返回未来的值：不存在 R^i^ → W^i^
- **(4.1.2)** 读操作不能跳过最近一次写入：不存在 W^i^ → W^j^ → R^i^
- **(4.1.3)** 读操作单调（仅原子寄存器需要）：如果 R^i^ → R^j^，则 i ≤ j

常规寄存器需满足 (4.1.1) 和 (4.1.2)；原子寄存器还需满足 (4.1.3)。

## 3. 寄存器构造链条

从最弱的 SRSW 安全布尔寄存器出发，逐级构造出全部寄存器类型：

| 步骤 | 输入 | 输出 | 关键技巧 |
|------|------|------|----------|
| 1 | SRSW 安全 | **MRSW 安全** | 每个读线程一个单元；写者写入所有单元 |
| 2 | MRSW 安全布尔 | **MRSW 常规布尔** | 仅当值变化时才写入底层寄存器 |
| 3 | MRSW 常规布尔 | **MRSW 常规 M-值** | 一元编码：置位对应索引，逐位升序扫描 |
| 4 | SRSW 常规 | **SRSW 原子** | 时间戳 + 每次读取记忆最高时间戳值（lastRead） |
| 5 | SRSW 原子 | **MRSW 原子** | n×n 表：读列取最大时间戳，写行告知他人（间接帮助） |
| 6 | MRSW 原子 | **MRMW 原子** | 面包房式时间戳：扫描全部取 max+1，字典序 (stamp, ID) |

### 构造要点

- **步骤 1**：read() 读自己对应的单元，write() 循环写所有单元
- **步骤 2**：布尔值相同则无需写——规避"安全寄存器重叠时返回任意值"的问题
- **步骤 3**：写入时先置位再按降序清除低位；读取按升序找第一个为 true 的位。关键是"从 j 前进时必有更高位为 true"的不变式
- **步骤 4**：时间戳单调递增，读取时取 max(新读, 记忆值)，防止读回旧值
- **步骤 5**：对角线存真实值，读时扫描所在列取最大时间戳，写后把读取结果广播到所在行——**间接帮助**（一个线程告知其他线程它所读到的内容）
- **步骤 6**：写前扫描全部元素取最大时间戳 +1，写到自己对应的槽位；读时取最大时间戳的值

**结论**：所有寄存器类型在可计算性上**等价**。

**两大算法工具**：① **时间戳**（区分新旧值）；② **间接帮助**（线程间传递所读取的信息）。

## 4. 原子快照

**原子快照**（atomic snapshot）：以原子方式读取 MRSW 寄存器数组的瞬时视图，可用于备份或设置检查点。

接口：`update(v)` 写入自己对应的寄存器，`scan()` 返回数组快照。

### 4.1 无阻塞快照（SimpleSnapshot）

- 每次 update 递增时间戳（StampedValue）
- **收集**（collect）：非原子地逐个复制数组
- **干净的双重收集**：连续两次收集时间戳完全相同 → 期间无更新 → 第二次收集即有效快照
- scan() 重复收集直至检测到干净的双重收集
- update 无等待，scan 无阻塞（仅当无冲突的 update 干扰时才保证完成；否则可能被反复打断而无法完成）

> 双重收集必须比较**时间戳**而非**值**——值可能反复改写后复原，导致误判"未变化"而得到错误快照。

### 4.2 无等待快照（WFSnapshot）

- 每个 update 在写入前先调用 scan()，并将快照附加到值上（stamp, value, snap）
- scan() 维护 moved[] 数组记录完成过 update（即发生**迁移**）的线程
- 若某线程被观察到**迁移了两次**，说明该线程在本次 scan 期间完成了一次完整 update——直接借用它已获取的快照作为结果
- 借用快照合法性的关键：该快照的拍摄时刻位于 scan() 的执行区间内，可作为线性化点

### 4.3 正确性证明

| 引理 | 内容 |
|------|------|
| 4.3.1 | 干净的双重收集返回的值必然存在于执行过程中的某个状态 |
| 4.3.2 | 观察到某线程迁移两次 → 最后一次读取的是它 update 后的新值 |
| 4.3.3 | scan() 返回的值位于其调用与响应之间的某个状态（嵌套归纳证明，最多 n-1 层） |
| 4.3.4 | scan/update 最多 O(n²) 步完成（n 次双重收集内必有干净收集或双重迁移） |
| 定理 4.3.5 | 图 4.20 是无等待快照实现 |

**相互帮助**范式：即使某线程中断另一个线程阻止其完成操作，中断线程可通过帮助完成被中断线程的操作来保证无等待性——这是设计多处理器算法的实用技巧。

## 5. 总结

本章通过研究寄存器的实现得出结论：使用功能最强大的寄存器实现的数据结构，可以使用功能最弱的寄存器来实现。功能最弱的寄存器（SRSW 安全布尔）在可计算性上等价于功能最强的寄存器（MRMW 原子），通过六步构造链条可以逐级构造出所有寄存器类型。

1. **一致性谱系**：安全 → 常规 → 原子，由 (4.1.1)~(4.1.3) 三个形式化条件精确刻画（按寄存器类型分别适用）
2. **构造方法学**：时间戳（区分新旧）+ 间接帮助（线程间传播信息）是贯穿全章的两大算法工具
3. **快照实现**：从无阻塞（干净双重收集）到无等待（迁移帮助 + 快照重用）的演进
4. **理论意义**：寄存器类型（安全/常规/原子）在可计算性上等价——即使硬件只提供最弱的寄存器，也能构造出最强的原子寄存器。

但上述结论仅限 read/write 寄存器内部，更强的同步原语（如 CAS）具有更高的共识数，无法由 read/write 寄存器构造。该结论与第 2 章存储单元下界相呼应——它促使实际体系结构引入更强的同步指令。
