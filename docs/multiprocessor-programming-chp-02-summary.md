<h1 align="center">多处理器编程的艺术</h1>
<h2 align="center">第二章 互斥 总结</h2>

## 1. 主题与核心思想

互斥是多处理器程序设计中最常见的协作形式。本章介绍基于读写共享存储的经典互斥算法（已不实际使用，但体现同步领域算法设计与正确性证明的典型问题），并给出一个**不可解性证明**：任何无死锁的互斥算法在最坏情况下至少需要 n 个存储单元——这正是硬件需要比读写更强的同步操作（如 RMW/CAS）的理论动因。

## 2. 时间与事件

- 线程可看作**状态机**，状态切换即**事件**；事件**瞬时发生**，任意两个事件时间戳互不相同。
- 事件上"先于"关系（→）是**全序**；时间间隔上的→是**偏序**——重叠的间隔之间不存在→，称为**并发**。

## 3. 临界区与锁特性

- **临界区**：一次只能由一个线程执行的代码块；其特性即**互斥**。
- Lock 接口：`lock()`（进入前）、`unlock()`（离开前）。获取锁后执行临界区，调用 unlock 释放。
- 三个理想特性：
  - **互斥**：任何时刻最多一个线程持有锁（安全特性）。
  - **无死锁**：若有线程调用 lock/unlock 后始终未返回，必有其他线程能成功获取/释放锁（活跃特性）。
  - **无饥饿**（=无锁定性）：每个尝试的线程最终都成功（活跃特性）。无饥饿蕴含无死锁。

## 4. 双线程解决方案

- **LockOne**：各自 flag 置 true，等待对方 flag 变 false。满足互斥，但两线程交错时死锁（两 flag 同时为 true）。
- **LockTwo**：单个 victim 字段，写自己 ID 后等 victim 变成对方。满足互斥，但只有并发运行才成功，单线程会死锁。
- **Peterson 锁**：两者结合（flag + victim）。满足**互斥**与**无饥饿**（因此也满足无死锁）——最简洁优雅的双线程互斥算法。锁的 while 条件：`flag[j] && victim == i`，即"对方有兴趣且自己是受害者"时才等待。

## 5. 死锁与活锁

- **死锁**（狭义）：系统进入某种状态，线程无法继续执行（如 LockOne/LockTwo 中两线程都在 while 循环中等待停滞）。
- **活锁**：线程持续执行但互相抵消进展，永到不了终点（未阻塞，但同样无法完成任务）。
- **无死锁特性同时排除狭义死锁与活锁**。图 2.7 的 Livelock 算法：不会陷入狭义死锁（总存在调度让某线程继续），但可能活锁 → 因此**不满足无死锁**。

## 6. 过滤锁

将 Peterson 锁泛化到 n 个线程：n-1 个"级别"（level）等待室，每层一个 victim 字段过滤出一个线程。两个不变量：至少有一个线程会尝试成功进入级别 L；若**多于一个线程**试图进入级别 L，则至少有一个线程会被阻塞。满足互斥与无饥饿，但不公平——线程可能被任意多次超越。

## 7. 公平性与面包房锁

- **公平性**：把 lock() 分为**入口区**（有界无等待，有限步内完成）与**等待区**（可无限步）。**先到先服务**（FCFS）：入口区先完成的线程先进入临界区。
- **面包房锁**：取号机模型。入口区取号 `label[i] = max(所有 label)+1`，等待直到没有"flag 升起且 (label,k) 字典序更小"的线程。字典序 `<<`：`label[i]<label[j]` 或 `label[i]==label[j] 且 i<j`，用于打破并发取号的平局。标签单调递增。满足互斥、无饥饿、FCFS。

## 8. 有界时间戳

面包房锁的标签无限增长，长运行系统会溢出（如千年虫、2038 年 time_t 问题）。标签即**时间戳**，需要两种能力：**扫描**（读他人时间戳）与**标记**（分配更晚的时间戳）。实现有界时间戳系统需要无等待特性（构造耗时），本章选择研究**串行**时间戳系统（扫描+标记为一个原子步骤），其基本原理相同。

## 9. 存储单元下界

- **结论**：任何满足无死锁的互斥算法，最坏情况下至少需要 **n** 个不同的存储单元（读写型）。
- **原因**：只靠 load/store 访问的单元，某线程写入的数据在他人读取前**可能被覆盖**——读写不具备原子 RMW 的"不可覆盖"能力。
- **意义**：这是推动硬件提供比读写更强的同步操作（如 RMW、CAS）的根本原因，为后续实用互斥算法奠定理论基础。

## 核心收获

- 经典锁算法（Peterson、过滤锁、面包房）展示互斥证明的典型推理：用"→"偏序构造循环矛盾。
- 读写的内在局限（可覆盖性）决定了下界，引向更强大的同步原语——衔接第 4、5 章的寄存器与共识数理论。
