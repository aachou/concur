<h1 align="center">多处理器编程的艺术</h1>
<h2 align="center">第三章 并发对象 总结</h2>

## 1. 主题与核心思想

并发对象的行为可用两个特性描述：

- **正确性**（安全特性）：并发执行等价于某种串行执行。
- **演进性**（活跃特性）：方法调用能否在有限步内完成。

本章阐述三种正确性条件（顺序一致性、线性一致性、静态一致性）和多种演进条件，并比较它们的强弱、是否可组合、是否阻塞。

**核心准则**：若能以某种方式把并发执行映射到串行执行，就只需分析串行执行的行为——这正是三种正确性条件的基础。

## 2. 串行对象

对象 = 数据 + 方法；方法行为用**前置条件**（调用前状态）和**后置条件**（调用后状态 + 返回值）描述，副作用即状态变化。这类文档称为**顺序规范说明**：合法顺序历史记录的集合。

多线程下的问题：方法调用时间重叠，"执行顺序"失去意义，中间状态也变得模糊，前置/后置条件不再适用——需要用正确性条件来规范并发执行。

## 3. 顺序一致性

由两条原理定义：

- **原理 3.3.1**：方法调用按串行顺序执行（太弱，单用不实用）。
- **原理 3.3.2**：程序次序（单线程内的方法调用顺序）必须保持。

**定义**：存在一种对全部方法调用的排序，满足（1）与程序次序一致；（2）符合对象的顺序规范。

**特性**：

- **不保持实时次序**：跨线程不重叠的调用（如先完成入队 x、后入队 y，y 却先出队）也可以重排，仍满足顺序一致性。
- **非阻塞**：挂起调用总能找到一个满足顺序一致性的响应，不会强制阻塞。
- **不可组合**：多个各自顺序一致的对象组合后，整体可能不满足顺序一致性（图 3.8 可构造出排序环，矛盾）。这是它最严重的缺陷。

## 4. 线性一致性

**原理 3.4.1**：每个方法调用在调用与响应之间的某个时刻**立即生效**——即保持实时次序。比顺序一致性更强：每个可线性化执行都满足顺序一致性，反之不然。

**可线性化点**：方法生效的瞬间。基于锁的实现中，临界区内任何点都可作线性化点；无锁实现中通常是效果对其他调用可见的那个单步（如 deq 更新 head 的时刻）。

**特性**：

- 与顺序一致性一样**非阻塞**。
- **可组合**：多个可线性化对象组合后仍可线性化（定理 3.6.3）。这是描述大规模系统的关键，故本书数据结构大多可线性化。
- 区别仅在**外部一致性**：只通过单个共享对象通信的线程区分不出二者，只有能观察实时次序的外部观察者才能看出差别。

## 5. 静态一致性

**原理 3.5.1**：被一段**静态时间**（无挂起调用）分隔的方法调用必须按实时次序执行。仅要求对象静止时强制排序，换取更廉价高效的实现。

**特性**：

- 与顺序一致性**不可比**：存在非静态一致的顺序一致执行，反之亦然；静态一致性不保持程序次序。
- **非阻塞**；**可组合**。
- 线性一致性强于二者：可线性化对象既是静态一致的又是顺序一致的。
- 例子：静态一致计数器 = **索引分发**机制（音乐椅类比）——返回的序号不重复、不遗漏，但不一定按调用顺序。

## 6. 演进条件

演进条件要求提供**具体的实现方法**来生成响应（而非像正确性那样只保证响应存在）。

| 条件 | 保证 | 演进 | 阻塞 | 独立 |
|---|---|---|---|---|
| **无等待**（wait-free） | 每个调用在有限步内完成（每个执行线程都演进） | 最大 | 非阻塞 | 独立 |
| **无锁**（lock-free） | 某些调用在有限步内完成（系统整体演进） | 最小 | 非阻塞 | 独立 |
| **无阻塞**（obstruction-free） | 独立执行时有限步内完成（无冲突调度假设） | 最大 | 非阻塞 | 依赖 |
| **无死锁**（deadlock-free） | 有线程在锁不被持有时取得演进 | 最小 | 阻塞 | 依赖 |
| **无饥饿**（starvation-free） | 每个线程在锁不被持有时取得演进 | 最大 | 阻塞 | 依赖 |

关键点：

- 无等待 ⊃ 无锁（反之不然）；若程序只执行有限个调用，二者等价。
- **独立**演进条件（无等待/无锁）不依赖调度策略，任何平台都工作；**依赖**演进条件（无阻塞/无死锁/无饥饿）需要底层平台保证（公平调度 / 独立执行），但实现通常更简单高效。
- 阻塞实现中，单线程延迟会阻止其他线程演进；基于锁的实现最多只能保证阻塞的演进条件。
- **争用管理**：无阻塞实现依赖暂停有冲突的线程，常用**退避**（back-off）机制。

## 7. 内存一致性模型

程序读写的内存可视为一个单一共享对象，其正确性特性即**内存一致性模型**。早期程序假定内存顺序一致，但现代多处理器会重排读写，并非顺序一致，需提供同步原语抑制重排（如 Java volatile）。第 2 章的锁算法隐含此假设，实际系统中需显式声明。

## 8. 如何选择

- **正确性**按需求选：打印服务器可用静态一致队列；银行需顺序一致；股票交易需可线性化（保证公平）。
- **演进**按需求选：同一对象的不同方法也可用不同演进保证（如防火墙查表用无等待、更新用互斥）。
- 理想是"可线性化硬件 + 可线性化数据结构 + 好性能"，但现状是硬件通常连顺序一致都不保证——本书的其余章节将介绍实现这一目标的路线图。
