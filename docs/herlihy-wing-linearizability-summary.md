## 1. 为什么需要线性一致

两个线程对一个共享计数器 counter 各执行一次递增操作。我们希望最终 `counter = 2`，但如果两个线程同时读取 `counter = 0`，那么最终 `counter = 1`：

```
线程 A: 读 x → 0
线程 B: 读 x → 0
线程 A: 写 x ← 1
线程 B: 写 x ← 1
```

任何顺序执行（例如 A 做完 B 再做）都会得到 2。

问题不是代码写错了——单线程下它从不出错。问题是：没有一个标准来**判断一个并发执行是否可以被认为是正确的**。Herlihy & Wing 给出的答案就是线性一致性。

## 2. 线性一致的定义

### 2.1  顺序规约

**顺序规约**定义了一个数据类型在顺序执行的情况下每个操作的行为规范，例如：

- 栈：Pop 返回最近 Push 且尚未 Pop 的值，操作完成后移除栈顶的节点（LIFO）
- 队列：Deq 返回最早 Enq 且尚未 Deq 的值，操作完成后移除队列头部的节点（FIFO）

> *一个操作的行为规范由前置条件和后置条件组成。前置条件指操作发生前数据类型的状态，后置条件指操作发生后数据类型的状态以及返回值。*

### 2.2 历史

一次并发执行的全部事件按时间排成序列，称为**历史**。一个事件是某个操作的 invocation（调用）或 response（返回）。

```
时间 →
线程 A:   Enq(1)调用 ────── Enq(1)返回
线程 B:              Deq()调用 ────────── Deq()返回1
```

- 从调用到返回的区间是操作"正在执行"的时间段
- 时间段重叠的两个操作叫并发操作，不重叠的叫非并发操作

> *为简化讨论，本文默认所有操作最终都会完成；对于未完成操作，可以通过补全或忽略它们来处理。*

### 2.3 可线性化

一个历史要被称为**可线性化**的，需要存在一个合法的顺序执行（或者说操作全序） S，使得 S 的执行结果与原历史一致，且保留原历史中非并发操作的实时次序。

S 称为这个历史的线性化。

### 2.4 线性化点

线性化点是一个操作在其调用之后、返回之前的某个时刻原子地完成的时间点。按线性化点的时间顺序对操作排序，就可以构造这些操作的一个符合实时次序的顺序执行 S。剩下的唯一问题是：S 是否符合该数据类型的顺序规约？

- 符合 → 这个历史是可线性化的
- 找不到这样的线性化点，或任何 S 都不符合顺序规约 → 这个历史是不可线性化的

### 2.5 数据结构满足线性一致

一个数据结构的实现满足线性一致性，当且仅当它所有可能的并发历史都是可线性化的。

## 3. 证明 Treiber Stack 是线性一致的

```
push(x):
  n = new Node(x)
  loop
    t = top
    n.next = t
    if CAS(&top, t, n): return

pop():
  loop
    t = top
    if t == null: return EMPTY
    n = t.next
    if CAS(&top, t, n): return t.val
```

**线性化点**：push 和 pop 都以成功的 CAS 指令为线性化点。pop 在空栈时读到 `t == null` 的时刻就是其线性化点。失败的 CAS 没有效果，没有线性化点。

按成功 CAS 的时间排序得到操作序列 S。每个 push 的成功 CAS 在栈顶加一个新节点；每个 pop 的成功 CAS 移除栈顶节点并返回它的值。S 符合 LIFO——最后 push 的最先被 pop。这说明 S 满足栈的顺序规约，因此 Treiber Stack 的所有并发历史都是可线性化的——它满足线性一致性。

> *注：实际实现还需解决 ABA 问题，配合 hazard pointer 或 EBR 管理内存回收。这是工程问题，不影响线性一致性判断。*

## 4. 与其他一致性模型对比

|                          | 线性一致性 | 顺序一致性 |
| ------------------------ | ---------- | ---------- |
| 保留非并发操作的实时次序 | 是         | 否         |
| 可组合                   | 是         | 否         |

**实时顺序**：如果 A 返回后才调用 B，线性一致性要求 S 中 A 必须在 B 之前。顺序一致性没有这个约束—— A 可以排在 B 之后。

**可组合性**：线性一致性是可组合的——只要每个对象满足线性一致，那么由这些对象构成的系统也是线性一致的。两个顺序一致性对象组合一起，整体不一定是顺序一致的。

## 5. 总结

线性一致性（Linearizability）是 Herlihy & Wing 提出的并发对象正确性条件。它要求**每个操作在其调用之后、返回之前的某个时刻原子地完成（这个时刻称为线性化点）**。

判断一个并发执行是否正确，就是给每个操作找线性化点，按线性化点的时间顺序构造操作的顺序执行，看这个顺序执行是否符合数据类型的顺序规约。

[这篇论文](https://cs.brown.edu/people/mph/HerlihyW90/p463-herlihy.pdf)是并发理论的基石，奠定了并发对象正确性的标准。
